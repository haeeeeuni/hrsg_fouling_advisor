# 07. 플랜트 데이터 요청 체크리스트

관련 요구사항: CHK-1 ~ CHK-7

---

## 1. 목적

정확한 평가는 필요한 데이터를 빠짐없이 받는 데서 시작한다. 다년간의 세정 경험에서 정리한 **데이터 요청 항목**을
체크리스트로 제공하고, 요청 건별로 받은 항목을 관리한다. **계산기와 함께 앱의 핵심 기능이다.**

## 2. 항목 템플릿 (CHK-1, CHK-2)

- **CHK-1** 항목은 사내 데이터 요청 양식의 전 항목 + 추가 항목으로 구성한다.
- **CHK-2** 항목마다 다음을 가진다.

| 필드 | 설명 |
|---|---|
| `category` | 분류(아래 §2.1) |
| `name_ko` · `name_en` | 항목명(한·영 — 복사 문구에 쓴다) |
| `unit` | 단위(없으면 빈칸) |
| `is_required` | 필수 여부 — 진행률은 필수 항목 기준 |
| `why_needed` | 왜 필요한가(한 줄) — 상대방 설득용 |
| `source` | `FORM`(사내 양식) \| `ADDED`(앱에서 추가) |
| `order`, `is_active`, `is_placeholder` | 정렬, 사용 여부, 임시값 여부 |

### 2.1 분류와 시드 `[임시값]`

**사내 양식(스프레드시트)을 아직 받지 못했다.** 아래는 요구사항에 적힌 분류로 만든 가상 항목이다.
`[실무 논의]` 양식 원본을 받으면 관리자 모드에서 xlsx 로 가져와 교체한다. 가져온 항목은 임시값 표시가 풀린다.
시드는 46개 항목이다(`checklist/seed.py`).

| 분류 | source | 시드 항목 (단위) |
|---|---|---|
| 가스터빈 | FORM | GT 모델·제조사 / GT 출력(MW) / 대기온도(℃) / 대기압(kPa) / 상대습도(%) / IGV 개도(%) / 누적 운전시간(h)·기동 횟수 |
| 연료 | FORM | 연료 종류 / 연료 유량(Nm³/h) / 저위발열량(kJ/Nm³) / 연료 조성 |
| 배기가스 | FORM | GT 배기온도(℃) / 배기가스 유량(kg/s) / GT 배압(kPa) / HRSG 가스측 차압(kPa) / 굴뚝 온도(℃) / 덕트버너 사용 여부·연료량 |
| 급수 | FORM | 급수 유량(t/h) / 급수 온도(℃) / 급수 압력(bar) / 절탄기 입구 온도(℃) |
| 증기 | FORM | 압력단별 증기 유량(t/h)·압력(bar)·온도(℃) / ST 출력(MW) |
| 배출가스 | FORM | NOx(ppm) / CO(ppm) / O₂(%) / 암모니아 주입량 |
| 열교환 모듈 사양 | FORM | 모듈 배치도 / 튜브 재질·외경·두께 / 핀 형태·높이·피치·두께 / 모듈별 전열면적(m²)·열 수 |
| 설계값 | FORM | 설계 열정산(Heat Balance) / 설계 배압(kPa) / 설계 굴뚝 온도(℃) / 설계 핀치·어프로치(℃) |
| 핀치·어프로치 | ADDED | 압력단별 드럼 압력(bar) / 절탄기 출구 급수 온도(℃) / 증발기 출구 가스 온도(℃) |
| 일정·현장 조건 | ADDED | 희망 세정 시기·가용 정지 기간 / 현장 접근 경로·작업 공간 / 점검구 위치 / 유틸리티(전원·압축공기·용수) / 출입·안전 절차 |
| 데이터 범위 | ADDED | 운전 데이터 기간(세정 전후) / 기록 주기(분) / 파일 형식 |

## 3. 요청 건 (CHK-3, CHK-4)

- **CHK-3** 사용자는 **요청 건**을 만든다. 이름은 자유 입력(예: "10월 A 사이트 사전 평가")이고 메모·희망 회신일을 선택 입력한다.
  - 만들 때 그 시점의 활성 템플릿 항목을 **복사**해 둔다. 이후 템플릿이 바뀌어도 진행 중인 요청 건은 바뀌지 않는다.
    관리자가 템플릿을 바꾸면 기존 요청 건에 "새 항목 추가하기" 버튼을 보여 준다(사용자가 선택).
  - 항목별로 **받음 / 미수신 / 해당 없음**을 체크하고 메모를 남긴다. 받음으로 바꾸면 날짜가 기록된다.
  - 진행률 = 받음 ÷ (필수 항목 − 해당 없음), 필수 기준. 분류별 진행률도 보여 준다.
  - 상태: `진행 중` → 필수 항목을 다 받으면 `완료`(자동), 다시 미수신이 생기면 `진행 중`(자동) / 사용자가 `보관` 가능.
    보관한 건은 기본 목록에서 숨기고 보관함에서 본다. 보관을 해제하면 체크 상태에 맞춰 진행 중·완료로 돌아간다.
- **CHK-4** 요청 건은 **만든 사람만** 보고 고친다. 관리자도 내용은 보지 않는다(건수만 집계).
- 요청 건 이름에 고객사·발전소 이름을 쓸 수 있다. 이 데이터는 LLM 에 보내지 않고 앱 밖으로 나가지 않는다.

## 4. 이메일용 복사 (CHK-5)

- **CHK-5** "미수신 항목 복사" 버튼은 미수신 항목을 이메일 본문 형식으로 **클립보드에 복사**한다. 이메일을 보내지는 않는다.
  - 언어 선택: 한국어 / 영어. 분류별로 묶고, 항목명 · 단위 · (필수 표시) · 왜 필요한가를 한 줄씩 쓴다.
  - 머리말·맺음말 문구는 관리자 설정(`chk_email_header_ko/en`, `chk_email_footer_ko/en`)이다.
  - "전체 항목 복사"(처음 요청할 때)도 제공한다.
  - 클립보드 API 를 쓸 수 없는 환경(비보안 컨텍스트)에서는 텍스트 상자에 펼쳐 수동 복사하게 한다.

## 5. 관리 (CHK-6)

- **CHK-6** 관리자는 템플릿 항목을 추가·수정·정렬(같은 분류 안에서 위·아래)·사용 중지하고, xlsx 로 가져오고 내보낸다.
  - xlsx 머리글: `category, name_ko, name_en, unit, is_required, why_needed_ko, why_needed_en, is_calculator_input, source, order, is_active`
    ("내보내기" 파일과 같다). `(category, name_ko)` 가 같으면 수정, 없으면 추가한다. 동기로 처리한다(1,000행 이하).
  - 삭제는 사용 중지다. 이미 만든 요청 건의 복사본은 영향을 받지 않는다.
  가져오기는 전부 아니면 전무(검증 실패 행이 있으면 행 번호와 사유를 보여 주고 저장하지 않는다).

## 6. 계산기 연계 (CHK-7)

- **CHK-7** 계산기 입력에 대응하는 항목(GT 모델, 출력, 배압, 굴뚝 온도, 드럼 압력 등)은 항목에 "계산기 입력" 표시를 붙인다.
  1차 범위에서는 표시만 한다. 받은 값을 계산기에 자동으로 채우는 기능은 범위 밖이다(값을 저장하지 않기 때문 — 체크리스트는 수신 여부만 관리한다).

## 7. 수용 기준 (AC)

- [ ] AC-07-1 새 요청 건을 만들면 활성 템플릿 항목이 모두 복사되고 진행률이 0 % 다.
- [ ] AC-07-2 필수 항목을 모두 받음으로 체크하면 상태가 `완료`가 된다. "해당 없음"은 분모에서 빠진다.
- [ ] AC-07-3 관리자가 템플릿을 바꿔도 기존 요청 건의 항목은 그대로다.
- [ ] AC-07-4 미수신 항목 복사 결과가 분류별로 묶이고, 영어 선택 시 영어 항목명이 쓰인다.
- [ ] AC-07-5 다른 사용자의 요청 건 ID 로 조회·수정하면 404 다.
- [ ] AC-07-6 시드 직후 핀치·어프로치 3개 항목과 일정·현장 조건 항목이 있다.
- [ ] AC-07-7 모바일 폭(360px)에서 체크·메모·복사가 모두 된다.
