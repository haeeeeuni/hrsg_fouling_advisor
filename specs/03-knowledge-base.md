# 03. 지식 베이스 (문서 · 임베딩 · 검색)

관련 요구사항: KB-1 ~ KB-10

---

## 1. 목적

질의응답의 근거가 되는 **회사·제품·기술 자료**를 관리자가 등록하고, 검색 가능한 형태(pgvector)로 저장한다.

## 2. 문서 분류 (KB-1)

| 분류 | 코드 | 예 |
|---|---|---|
| 회사 정보 | `COMPANY` | 회사 소개, 서비스 범위, 연락 창구 |
| 제품·서비스 | `PRODUCT` | 세정 공법·장비 소개, 브로슈어 |
| 기술 자료 | `TECHNICAL` | 점검·모델링 보고서 샘플, 기술 노트 |
| 사례 | `CASE` | 케이스 스터디(비식별) |

- **KB-1** 관리자는 문서를 생성·조회·수정·삭제한다. 문서마다 제목, 분류, 설명(선택), 사용 여부, 입력 방식을 가진다.

## 3. 입력 방식 (KB-2 ~ KB-4)

- **KB-2 텍스트:** 관리자 화면 편집기에 직접 입력한다(마크다운 허용). 회사 정보처럼 짧은 자료에 쓴다.
- **KB-3 Word(.docx):** 본문 문단과 표를 추출한다. 제목 스타일(Heading 1~3)을 절 경계로 쓴다. `.doc`(구형)은 지원하지 않는다.
- **KB-4 PDF:** 페이지별 텍스트를 추출하고 페이지 번호를 청크에 남긴다.
  - 추출 텍스트가 페이지당 평균 `pdf_min_chars_per_page`(기본 30)자 미만이면 **스캔 PDF 로 보고 거부**한다("텍스트를 추출할 수 없는 PDF 입니다. OCR 은 지원하지 않습니다").
- 공통 제한: 파일 최대 `kb_max_file_mb`(기본 20)MB, 확장자 + MIME 검증, 암호 걸린 파일 거부.
- **수정:** 텍스트는 본문 편집, 파일은 새 파일로 교체. 수정하면 문서 `version` 이 올라가고 다시 색인한다.
- **삭제:** 문서와 청크·벡터를 함께 지운다. 과거 대화의 출처 기록에는 "삭제된 문서"로 표시된다.
- **원본 파일은 PostgreSQL 에 저장한다**(BinaryField). Render 등 PaaS 디스크는 재배포 때 사라지기 때문이다.
  원본은 관리자만 내려받을 수 있다.

## 4. 색인 파이프라인

```
문서 저장 ─▶ 202 + job_id ─▶ [워커] 텍스트 추출 ─▶ 정규화 ─▶ 민감어 검사 ─▶ 청크 분할 ─▶ 임베딩 ─▶ 저장
```

- 상태: `PENDING` → `INDEXING` → `READY` | `FAILED`(사유 저장). `READY` 이고 사용 중인 문서만 검색된다.
- 색인은 `common/jobs.py` 의 job 패턴을 쓴다(Celery 워커, Render 무료 플랜에서는 즉시 실행).
- 재색인은 원자적으로 한다 — 새 청크를 모두 만든 뒤 한 트랜잭션에서 옛 청크와 교체. 색인 중에도 옛 버전으로 검색된다.
- 전체 재색인: 청크 설정이나 임베딩 모델을 바꾸면 관리자가 "전체 재색인"을 실행한다. 화면에 이 사실을 안내한다.

### 4.1 청크 분할

| 설정 키 | 기본값 | 설명 |
|---|---|---|
| `kb_chunk_size_chars` | 800 | 청크 최대 길이(문자) |
| `kb_chunk_overlap_chars` | 150 | 앞 청크와 겹치는 길이 |
| `kb_chunk_min_chars` | 100 | 이보다 짧은 꼬리 청크는 앞 청크에 붙인다 |

- 경계 우선순위: 절 제목 → 빈 줄(문단) → 문장 끝 → 글자 수.
- 청크마다 문서 ID, 문서 버전, 순번, 절 제목, 페이지(PDF), 본문, 임베딩, 전문 검색용 텍스트를 저장한다.
- 청크 앞에 "문서 제목 > 절 제목"을 붙여 임베딩한다(짧은 청크의 맥락 보강).

## 5. 임베딩 (KB-5) — 추천안

**로컬 다국어 임베딩 모델을 기본으로 한다.**

| 근거 | 설명 |
|---|---|
| 채팅 LLM 과 분리 | 관리자가 채팅 공급자를 Claude ↔ GPT ↔ Gemini 로 바꿔도 색인을 다시 할 필요가 없다. Claude 는 임베딩 API 를 제공하지 않는다 |
| 추가 키 없음 | 채팅에 Claude 를 쓰면서 임베딩용 OpenAI 키를 따로 받을 필요가 없다 |
| 외부 전송 축소 | 색인할 때 문서 전체가 외부로 나가지 않는다. 질문 시 선택된 청크만 LLM 에 간다 |
| 한·영 지원 | 다국어 모델이라 한국어 문서에 영어 질문도 검색된다 |

- **런타임:** ONNX Runtime 기반(PyTorch 미사용 — 이미지 크기·메모리 때문). 모델 파일은 이미지 빌드 시 내려받아 둔다.
- **모델 후보:** `intfloat/multilingual-e5-small`(384차원) — 1순위. e5 계열은 질의에 `query: `, 청크에 `passage: ` 접두를 붙여야 한다.
- **구현 첫 단계에서 확정한다:** 가상 문서·질문 세트로 ① 메모리 사용량(Render 무료 512MB 안에 드는지),
  ② 상위 5개 안에 정답 청크가 들어오는 비율을 재고, 미달하면 대안으로 바꾼다.
  - 대안 A: 다른 다국어 경량 모델(384~768차원)
  - 대안 B: 외부 임베딩 API(OpenAI 등) — 메모리 문제는 사라지지만 별도 키와 외부 전송이 생긴다
- **임베딩 모델은 관리자 설정이 아니다.** 벡터 차원이 DB 컬럼(`vector(384)`)과 인덱스에 묶여 있어 바꾸려면
  마이그레이션 + 전체 재색인이 필요하기 때문이다. 환경 변수 `EMBEDDING_MODEL` 로 지정하고, 관리자 화면에는 읽기 전용으로 보여 준다.
  (기술 프롬프트의 "RAG 튜닝 설정 전부 DB"에서 예외로 둔 유일한 항목이다 — `changes-2026-10.md` §3)
- 임베딩 모델 교체 절차: 마이그레이션(차원 변경) → `python manage.py reindex_all` → 검증. 개발자 작업이다.

## 6. 저장 (KB-6)

- **KB-6** 청크와 임베딩은 PostgreSQL + **pgvector** 에 저장한다(`09-data-model.md`).
  - 벡터 컬럼: `vector(384)`, 거리: 코사인. 인덱스: HNSW(`vector_cosine_ops`).
  - 전문 검색: 한국어 형태소 분석기가 없으므로 `pg_trgm` 삼중자(trigram) 인덱스를 쓴다. 제품명·모델명(예: "7FA") 같은 정확한 단어 매칭을 보완한다.
- DB 이미지는 pgvector 확장이 있는 것으로 바꾼다(`13-nonfunctional.md` §6). 마이그레이션에서 `CREATE EXTENSION IF NOT EXISTS vector`, `pg_trgm`.

## 7. 검색 (KB-7)

- **KB-7 하이브리드 검색:**
  1. 벡터 검색: 질문 임베딩과 코사인 유사도 상위 `rag_vector_candidates`(기본 20)개
  2. 키워드 검색: trigram 유사도 상위 `rag_keyword_candidates`(기본 20)개
  3. 두 목록을 RRF(Reciprocal Rank Fusion, `rag_rrf_k` 기본 60)로 합친다
  4. 벡터 유사도가 `rag_min_similarity`(기본 0.30) 미만인 청크는 버린다
  5. 상위 `rag_top_k`(기본 5)개를 LLM 에 보낸다. 같은 문서의 인접 청크는 합쳐 하나로 보낸다
- `rag_hybrid_enabled`(기본 `true`)를 끄면 벡터 검색만 쓴다.
- **KB-8** 위 검색 파라미터와 §4.1 청크 설정, 시스템 프롬프트(`02` §4)를 포함한 **RAG 튜닝 설정은 전부 DB(`Setting`)에 저장**하고
  관리자 화면에서 바꾼다(`08` §4). 예외는 임베딩 모델 하나다(§5).
- 남은 청크가 하나도 없으면 LLM 에 "근거 없음"을 알리고 CHAT-2 규칙대로 답하게 한다.
- 검색 단계는 순수 함수와 쿼리 함수로 나눠 단위 테스트한다(`knowledge/services/retrieval.py`).

## 8. 민감어 사전과 비식별화 (KB-9)

- **KB-9** 관리자는 민감어(고객사·발전소 이름, 인명 등)를 등록한다. 대소문자·공백을 무시하고 매칭한다.
  - 색인 시: 문서 본문에서 민감어가 발견되면 **경고와 위치 목록**을 보여 준다. 관리자가 "그대로 색인"을 선택하지 않으면 색인하지 않는다.
  - 출력 시: 답변·출처 스니펫에서 가린다(`02` CHAT-7).
- 비식별화는 **업로드 전에 사람이** 한다. 앱은 2차 확인만 한다. `[실무 논의]` 비식별화 기준과 책임자, 민감어 초기 목록.
- 원문 파일과 전체 본문은 USER API 로 내려가지 않는다. USER 는 출처 제목과 짧은 스니펫만 본다.

## 9. 외부 전송 (KB-10)

- **KB-10** 질문할 때 검색된 청크(최대 `rag_top_k` 개)가 LLM 공급자에게 전송된다. 관리자 LLM 설정 화면에 이 사실을 표시한다.
- `[실무 논의]` 비식별 자료라도 외부 LLM 으로 보내도 되는지(협력사 보안 정책). 확정 전까지 **가상 문서로만** 검증한다.
