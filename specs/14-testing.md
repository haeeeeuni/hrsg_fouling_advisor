# 14. 테스트와 검수

관련 요구사항: ACC-1 ~ ACC-8

---

## 1. 원칙

- 검수 자료(검증 사례, 테스트 질문 정답지)를 받을 시점이 정해지지 않았다. **기능을 구현한 뒤 가상 데이터를 함께 만들어** 검증하고,
  실제 자료를 받으면 같은 구조에 넣어 다시 돈다. `[실무 논의]` 검수 자료 제공.
- **자동 테스트는 실제 LLM 을 부르지 않는다.** 가짜 공급자(`llm/providers/fake.py`)로 결정적으로 돈다.
  실제 LLM 품질(검수 4·5·6)은 별도 평가 스크립트로 수동 실행한다(비용·비결정성 때문).
- 같은 검증을 아래 계층에서 할 수 있으면 아래 계층에서 한다(순수 함수 → API → E2E).

## 3. 가상 데이터

| 자료 | 위치 | 내용 |
|---|---|---|
| 가상 지식 베이스 | `backend/fixtures/virtual_kb/` | 가상 회사 소개·공법 브로슈어·점검 보고서·케이스 스터디 8~12건(텍스트·docx·PDF 섞어서). 실존 회사·발전소·인명 금지. 민감어 검사용으로 가상 발전소명("가상발전 1호기")을 일부 문서에 넣는다 |
| 가상 질문 세트 | `backend/fixtures/eval/questions.yaml` | 20문항 이상: 문서 근거 질문 10 · 계산 질문 5 · 근거 없음 질문 2 · 민감 정보 요청 3, 한·영 섞어서. 문항마다 기대 출처 문서, 포함해야 할 핵심어, 기대 계산 도구·입력 |
| 가상 계산 사례 | `backend/calculator/tests/cases.yaml` | 10건: 입력 + 손계산 기대값. 정상·경보·트립·음의 Δ·회수 불가 경계 포함 |
| 가상 참조값 | `seed_defaults` | `06` §2.1, §3 |

- 넣는 명령: `python manage.py load_virtual_kb` (운영 DB 보호를 위해 `DEBUG` 이거나 `--force` 일 때만).
- 평가 스크립트: `python manage.py eval_chat --questions fixtures/eval/questions.yaml --out eval-report.md`
  - 문항별 답변·출처·카드·가드 결과를 기록하고 정답률(핵심어·출처·도구 일치 기준)과 근거 없는 수치 건수를 집계한다.
  - 실행할 때마다 공급자·모델·설정 스냅샷을 보고서 머리에 남긴다.

## 4. 계층별 테스트

### 4.1 백엔드 (`pytest` + `pytest-django`, PostgreSQL + pgvector)

- 순수 함수(`calculator/services`, `chat/services/guards.py`, `knowledge/services/chunking.py`·`retrieval` 의 점수 결합,
  `llm/providers/*` 의 형식 변환)는 DB 없이 돈다(`-m "not django_db"`). 커버리지 80 % 이상.
- 성질 기반 검증 예:
  - 계산: Δ 가 커지면 손실이 단조 증가, 회복률 1 → 0 이면 회수 효과 단조 감소, 같은 입력 = 같은 출력
  - 가드: 근거 집합에 없는 수치는 반드시 잡힌다, 근거 값의 반올림 표현은 통과한다
  - 청크: 모든 원문 글자가 최소 한 청크에 들어간다, 청크 길이 ≤ 설정값
- API: 권한 전수(비로그인 401, USER 의 관리자 API 403, 승인 대기 거부), 남의 리소스 404, 응답에 비밀 필드 없음.
- 공급자 어댑터: 각 SDK 의 HTTP 계층을 모킹해 정상·도구 호출·오류 6종을 재현.

### 4.2 프론트엔드 (`vitest`)

- 포맷터(`null` → "계산 불가"), 스토어, 디바운스·늦은 응답 무시, 테마 저장, 복사 문구 생성.

### 4.3 E2E (Playwright + Chrome)

이전 앱의 E2E 인프라(`playwright.config.ts`, `tests/support/*`, CI 워크플로)를 재사용한다. 규칙(`archive/v1-fouling-advisor/21-e2e-testing.md`)을 이어받는다:

- 역할·레이블 셀렉터를 쓴다(디자인 변경에 강하게).
- 로그인 스로틀(분당 10회)을 공유하므로 **저장된 관리자 세션을 재사용**하고 폼 로그인을 늘리지 않는다. 다른 사용자 로그인은 빈 쿠키로 시작한다.
- 데이터를 바꾸는 테스트는 `@mutates` 태그를 붙인다. 배포본 대상 실행에서는 자동 제외한다.
- E2E 는 **가짜 LLM 모드**로 띄운 서버를 대상으로 한다(`LLM_FAKE_MODE=1` — 개발·테스트 설정에서만 허용, `prod` 에서는 무시).
- 뷰포트 × 테마 4조합: 1280×800 · 390×844 × 라이트 · 다크(ACC-8). 타임존 Asia/Seoul, 로케일 ko-KR.
- **가입 스로틀:** E2E 는 한 IP 에서 여러 번 가입한다. Django 를 `THROTTLE_SIGNUP=1000/hour` 로 띄운다(CI 워크플로에 설정돼 있다).
  기본값(시간당 10회)으로 띄우면 두세 번째 실행부터 가입 테스트가 429 로 실패한다.
- 셀렉터는 접근성 이름 기준(`getByRole`)을 우선한다. `getByLabel(..., { exact: true })` 는 라벨의 **글자 그대로**를 보므로
  필수 표시 `*` 가 붙은 라벨과 맞지 않는다.
