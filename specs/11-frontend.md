# 11. 프론트엔드

관련 요구사항: UI-1, UI-2, UI-7 ~ UI-9. 스택은 `AGENTS.md` §2(Vue 3 `<script setup>`, Vite, Vue Router, Pinia, Bootstrap 5.3, Chart.js).

- 라우트 가드는 앱 부팅 시 `GET /api/auth/me/` 결과를 기다린 뒤 판정한다(새로고침 시 잘못된 리디렉션 방지).

## 2. 소개 화면 (UI-7)

- **UI-7** 첫 화면. 내용:
  1. 앱 이름 "HRSG 레퍼런스 앱"과 한 줄 소개
  2. 기능 3개 카드 — 질의응답 / 계산기 / 플랜트 데이터 요청 체크리스트. 무엇을 할 수 있는지 한두 줄
  3. 사용 방법 — ① 회원가입 → ② 관리자 승인 → ③ 로그인 후 기능 사용. 기능별 사용 팁
  4. 이용 안내 — 수치는 계산기로만 산출된다, 임시 참조값을 쓰는 동안 결과는 참고용이다, 민감 정보를 입력하지 말 것
- 문구는 `/api/app-info/` 또는 프론트 상수로 둔다(관리자 편집은 1차 범위 밖).

## 3. 헤더 (UI-2)

- **UI-2** 모든 화면 공통 상단 바: 좌측 앱 이름(→ `/` 또는 `/home`), 가운데(데스크톱) 기능 메뉴 3개,
  **우측 끝: 로그인 버튼 또는 사용자 메뉴**, 그 왼쪽에 라이트/다크 전환 버튼.
  - 비로그인: `로그인` 버튼 → ID·비밀번호 폼, "회원가입" 링크.
  - 로그인: 성명 드롭다운 — 내 정보, (관리자면) 관리자 모드, 로그아웃.
  - 로그인 실패·승인 대기 안내는 폼 안에 바로 표시한다(`01` §5 문구).
- 관리자에게는 승인 대기가 있으면 사용자 메뉴에 건수 배지를 단다.
- `must_change_password` 면 헤더 아래에 비밀번호 변경 배너를 고정한다.

## 4. 레이아웃 (UI-8)

- **UI-8** 사용자 화면은 **상단 바 + 본문** 구조다(사이드바 없음 — 기능이 3개뿐이고 모바일 우선).
  모바일 폭에서는 기능 메뉴가 햄버거 메뉴로 접힌다.
- 관리자 모드는 상단 바 + **좌측 사이드바**(데스크톱) / 오프캔버스(모바일, `lg` 미만).
- 질의응답은 데스크톱에서 대화 목록 + 대화창 2열, 모바일에서는 대화 목록을 드로어로.
- 계산기는 데스크톱에서 입력(좌) + 결과(우) 2열, 모바일에서 입력 → 결과 세로. 결과 상단의 상태·큰 숫자가 스크롤 없이 보이게 한다.

## 5. 상태 관리 (UI-9)

- **UI-9** Pinia 스토어는 다음으로 한정한다: `auth`(사용자·로그인 상태), `ui`(테마), `chat`(대화 목록·현재 대화·채팅 상태).
  계산기·체크리스트는 화면 지역 상태로 충분하다.
- API 호출은 `src/api/*.js` 모듈을 거친다(컴포넌트에서 axios 직접 호출 금지).
- 늦게 도착한 응답은 버린다 — 계산기 디바운스, 대화 전환 시 이전 대화 응답(이전 앱에서 같은 결함을 세 번 고쳤다).
- 202 job 은 기존 `useJobPolling` 을 재사용한다(문서 색인·가져오기).

## 7. 표기

- 숫자는 `utils/format.js` 의 공통 포맷터: 금액 `#,##0 원`(1억 이상은 "1.2억 원" 병기), MW 소수 1자리, 온도 `℃` 소수 1자리, 압력 `kPa` 소수 2자리.
- **계산 불가(`null`)는 "계산 불가"** 로 쓴다. `?? 0` 금지.
- 날짜는 KST. 서버의 UTC 값을 문자열 앞 10자로 자르지 않는다(이전 앱에서 세 번 난 버그).
